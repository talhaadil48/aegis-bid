2. Pretype these in separate terminal tabs

.venv\Scripts\python.exe -m scripts.demo --race
.venv\Scripts\python.exe -m scripts.demo --recover
.venv\Scripts\python.exe -m scripts.demo --bacula
.venv\Scripts\python.exe -m scripts.demo --evidence

--race uses bidder1 and bidder2 at the current eligible amount. Avoid manual bids during the race. --recover really stops the local Compose worker, retries one UUID 20 times and restarts it in a finally block. Successful output is ACCEPTED, matching_requests=1 and PASS. It writes only .cache/demo-recovery.json; historical measurements stay unchanged. --bacula lists existing Catalog jobs; --evidence only reads recorded reports.

Likely viva questions: concise answers

Exactly once? Stable UUID admission and one committed SQL effect; transport can redeliver. Why NATS? Durable command journal and retries; SQL intake and reconciliation close the publication gap. Why a Go gateway? Shared prepared frames and bounded coalescing reduce per-subscriber work. HA vs backup? HA handles a primary/node failure; WAL recovery restores a selected historical point, and remote copies address local loss. Production complete? No: real multi-zone exercise, independent-account backups, continuous production PITR/RPO proof, distinct-client capacity and the closed-auction admission guard remain.
